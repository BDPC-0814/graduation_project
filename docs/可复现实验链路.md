# 可复现实验链路

本文档给出一套不依赖实时机器波动的固定频率 vs 故障演化采样对照流程。

## 1. 生成标准回放轨迹

```powershell
.\.venv\Scripts\python demo\generate_replay_trace.py
```

默认会生成两份文件：

- `experiments/replay_profiles/heterogeneous_fault_trace.csv`
- `experiments/replay_profiles/heterogeneous_fault_events.csv`

其中：

- `trace.csv` 是三类设备共享的异构回放轨迹。
- `events.csv` 是 ground-truth 事件时间表，用于统一 latency 评估口径。

## 2. 在同一条轨迹上跑 fixed 与 evolution

固定频率：

```powershell
.\.venv\Scripts\python demo\evolution_sampling_experiment.py --mode fixed --device all --trace-file experiments\replay_profiles\heterogeneous_fault_trace.csv --duration 85 --output experiments\replay_fixed.csv --event-output experiments\replay_fixed_events.csv --outbox-db experiments\replay_fixed.db
```

故障演化采样：

```powershell
.\.venv\Scripts\python demo\evolution_sampling_experiment.py --mode evolution --device all --trace-file experiments\replay_profiles\heterogeneous_fault_trace.csv --duration 85 --output experiments\replay_evolution.csv --event-output experiments\replay_evolution_events.csv --outbox-db experiments\replay_evolution.db
```

说明：

- `--trace-file` 会启用回放适配器，所有设备按同一条标准轨迹推进。
- `--device all` 会一次性载入轨迹中的 `cpu0 / gpu0 / npu0`。
- 输出里的 `time` 字段会改为轨迹时间，而不是本地墙钟时间。

## 3. 用 ground-truth 事件评估

```powershell
.\.venv\Scripts\python demo\evaluate_metrics.py --fixed experiments\replay_fixed.csv --evolution experiments\replay_evolution.csv --ground-truth-events experiments\replay_profiles\heterogeneous_fault_events.csv --output-dir experiments\evaluation\latest
```

这个模式下：

- latency 不再由各自采样结果反推事件。
- fixed 和 evolution 会共享同一份事件时间表。
- 多设备场景下，采样间隔与冗余会按设备分别计算，再做模式汇总。

## 4. 一键脚本

也可以直接用：

```powershell
powershell -ExecutionPolicy Bypass -File demo\run_midterm_check.ps1 -Devices all -ReplayTrace experiments\replay_profiles\heterogeneous_fault_trace.csv -GroundTruthEvents experiments\replay_profiles\heterogeneous_fault_events.csv -Duration 85
```

如果只传 `-ReplayTrace`，脚本会优先在同目录下自动寻找匹配的 `events.csv`。
